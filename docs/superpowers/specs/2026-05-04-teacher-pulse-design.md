# Spec: Teacher Pulse ("Пульс преподавателя")

Дата: 04.05.2026
Автор: brainstorm + спецификация
Статус: утверждён, готов к реализации

---

## 1. Цель и не-цели

### Цель

Создать внутренний контур, который:

- дисциплинирует преподавателя в отправке ДЗ после уроков (мягкая эскалация);
- даёт единый экран здоровья всех учеников (светофор);
- присылает утреннюю сводку с планом дня и проблемами;
- между уроками отправляет ученикам персонализированные касания от имени преподавателя, основанные на заметках после уроков.

### Не-цели

- Геймификация, quiz, achievements, streak-счётчики для учеников (отдельная итерация).
- Сегментные рассылки (отдельная фича, в очереди IMPLEMENTATION_STATUS).
- Изменение существующих экранов. Добавляется только кнопка «Пульс» в админское меню.
- AI/LLM-сервисы для анализа заметок. Парсинг заметок - keyword/pattern, без внешних зависимостей.

---

## 2. Компоненты

Четыре компонента, один общий движок `pulse_engine`.

| # | Компонент | Адресат | Суть |
|---|-----------|---------|------|
| 1 | ДЗ-надзиратель (Homework Nudge) | Админ | 3-ступенчатая эскалация, если ДЗ не отправлено после урока |
| 2 | Экран «Пульс» (Health Dashboard) | Админ | Светофор всех учеников с кликом в карточку |
| 3 | Межурочные касания (Between-Lesson Touches) | Ученики | 1-2 персональных сообщения в неделю |
| 4 | Утренняя сводка (Morning Briefing) | Админ | Ежедневно в 09:00 МСК: уроки + проблемы |

---

## 3. Компонент 1: ДЗ-надзиратель (Homework Nudge Engine)

### Проблема

Преподаватель проводит урок, но ДЗ отправляет с задержкой или забывает. Ученик ждёт.

### Механика

Scheduler-джоб `homework_nudge` (каждые 30 минут) проверяет: был ли урок у ученика в течение последних 24 часов, и появилось ли после него новое ДЗ в таблице `homework`. Если нет - запускается эскалация.

### Ступени эскалации

| Ступень | Когда | Сообщение админу | Кнопки |
|---------|-------|------------------|--------|
| Мягкое | +2ч после урока | «Аня: урок закончился 2ч назад, ДЗ не отправлено.» | [Отправить ДЗ] |
| Настойчивое | +6ч (или 09:00 следующего дня, если урок вечерний) | «Аня ждёт домашку. Уже Nч без ДЗ.» | [Отправить ДЗ] [Пропустить] |
| Финальное | +24ч | «Аня: сутки без ДЗ после урока.» | [Отправить ДЗ] [Пропустить] [Урок был без ДЗ] |

### Эмодзи-маркеры ступеней

- Ступень 1 (мягкое): сообщение без цветового индикатора
- Ступень 2 (настойчивое): маркер предупреждения
- Ступень 3 (финальное): маркер проблемы

### Правила

- Кнопка «Пропустить» появляется только со ступени 2. На первой ступени - мягкий толчок без лёгкого выхода.
- Кнопка «Урок был без ДЗ» - только на ступени 3. Закрывает цепочку без вины.
- Если ДЗ отправлено (новая запись в `homework` для этого ученика после `lesson_date`) - цепочка автоматически закрывается.
- Тихие часы: 22:00-08:00 МСК. Nudge, попавший в тихие часы, откладывается на 08:00.
- Для пар: один nudge на пару, привязан к `primary_student_id`.
- Тон: тёплый, но настойчивый. Не «ВНИМАНИЕ! ПРОСРОЧЕНО!», а «Аня, наверное, ждёт - давайте отправим?»

### Таблица `homework_nudges`

```sql
CREATE TABLE IF NOT EXISTS homework_nudges (
    id SERIAL PRIMARY KEY,
    student_id BIGINT NOT NULL REFERENCES users(telegram_id),
    lesson_id INTEGER NOT NULL REFERENCES lessons(id),
    stage INTEGER NOT NULL DEFAULT 1,       -- 1, 2, 3
    sent_at TIMESTAMP NOT NULL DEFAULT now(),
    resolved_at TIMESTAMP,
    resolution TEXT,                         -- 'hw_sent', 'skipped', 'no_hw_needed'
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS homework_nudges_open_idx
ON homework_nudges (student_id)
WHERE resolved_at IS NULL;
```

### Callback-схема

- `nudge:hw:{student_id}` - переход к отправке ДЗ для ученика
- `nudge:skip:{nudge_id}` - пропустить (закрывает с resolution='skipped')
- `nudge:nohw:{nudge_id}` - урок без ДЗ (закрывает с resolution='no_hw_needed')

## 4. Компонент 2: Экран «Пульс» (Admin Health Dashboard)

### Проблема

Нет единой картины: кто отстаёт, у кого нет ДЗ, кто не платил. Приходится проверять каждого вручную.

### Механика

Новая кнопка «Пульс» на админском главном экране (рядом с «Сегодня»). Один экран, вся база одним взглядом.

### Вид экрана

```
Пульс - 4 мая, воскресенье

[красный] Аня К. - 2 дня без ДЗ, баланс 0
[красный] Игорь + Маша - 3 дня без урока, ДЗ не отправлено
[жёлтый] Дима Л. - баланс 1 урок
[зелёный] Катя С. - всё ок (streak 4 недели)
[зелёный] Олег Р. - всё ок
...

Итого: 2 проблемы, 1 внимание, 8 в порядке
```

### Логика светофора

| Цвет | Условие (любое из) |
|------|-------------------|
| Красный | Баланс 0 уроков; ИЛИ ДЗ не отправлено >24ч после урока; ИЛИ нет уроков >14 дней |
| Жёлтый | Баланс 1 урок; ИЛИ ДЗ не отправлено >6ч после урока; ИЛИ нет уроков 7-14 дней |
| Зелёный | Всё остальное |

### Правила

- Сортировка: красные сверху, потом жёлтые, потом зелёные. Проблемы наверху.
- Каждый ученик - кликабельная inline-кнопка, ведёт в его карточку.
- Для пар - одна строка с обоими именами, данные агрегированы по `primary_student_id`.
- Внизу - сводка-счётчик по цветам.
- Данные считаются на лету из существующих таблиц (`lessons`, `homework`, `payments`, `homework_nudges`). Отдельная таблица не нужна.
- Доступ также через slash-команду `/pulse` (scope: admin-only, аналогично `/today`).

### Callback-схема

- `admin:pulse` - открыть экран Пульса
- `pulse:student:{student_id}` - переход в карточку ученика

### Общий движок `pulse_engine`

Функция `compute_student_health(db, student_id) -> dict` возвращает:

```python
{
    "color": "red" | "yellow" | "green",
    "reasons": ["no_hw_24h", "balance_0"],
    "days_since_last_lesson": int,
    "days_since_last_hw": int | None,
    "balance": int,
    "open_nudges": int,
    "streak_weeks": int,
}
```

Используется и в экране «Пульс», и в утренней сводке, и в ДЗ-надзирателе.

## 5. Компонент 3: Межурочные касания (Between-Lesson Touches)

### Проблема

Между уроками бот молчит. Ученик не чувствует, что преподаватель о нём помнит.

### Механика

Scheduler-джоб `between_lesson_touches` (раз в час) выбирает учеников, которым пора отправить касание: короткое тёплое сообщение от имени преподавателя.

### Когда отправлять

Привязка к циклу уроков ученика. Касание приходит в середине межурочного промежутка:

```
send_at = last_lesson_date + (next_lesson_date - last_lesson_date) / 2
         +/- случайный сдвиг 2-4 часа
```

Ограничения:
- Не больше 2 касаний в неделю на ученика.
- Тихие часы: 22:00-09:00 МСК.
- Не отправлять в день урока (и так есть коммуникация).
- Не отправлять, если нет `teacher_comment` к последнему уроку и нет активного ДЗ.

### Источники контекста (откуда бот знает, что написать)

Основной источник: **`teacher_comment`** в таблице `lessons` (берётся заметка к последнему завершённому уроку ученика).

Парсинг свободного текста заметки (keyword/pattern):

1. Паттерны: «разобрали X», «тема: X», «сложно далось X», «задание: X», «повторить X», «проблема с X».
2. Если паттерн найден - бот извлекает фрагмент и подставляет в шаблон.
3. Если паттерн не найден - бот берёт первое предложение заметки целиком как контекст.
4. Fallback: если заметка короче 10 символов или непарсируемая - касание привязывается к ДЗ или цели ученика.

Дополнительные источники (существующие таблицы):
- `homework` - есть ли активное ДЗ, когда дедлайн.
- `lessons` - streak, давность последнего урока.
- `payments` - баланс (не слать мотивацию ученику с нулевым балансом).
- `users.goal_text` - личная цель ученика.
- `student_groups.shared_goal_text` - цель пары.

### Логика выбора касания

```
1. Есть свежий teacher_comment?
   -> Касание на основе темы/сложности/ДЗ из заметки
2. Нет заметки, но есть активное ДЗ с дедлайном?
   -> Мягкое напоминание о ДЗ
3. Нет ни того, ни другого?
   -> НЕ отправлять. Тишина лучше нерелевантного сообщения.
```

### Типы касаний (шаблоны)

| Тип | Когда | Пример | Персонализация |
|-----|-------|--------|---------------|
| Прогресс | Есть teacher_comment с темой | «{Имя}, на прошлом уроке разобрали {тема}. К следующему занятию попробуй заметить это в любом тексте на английском» | Имя, тема из заметки |
| Поддержка | Есть teacher_comment с упоминанием сложности | «{Имя}, если {тема} ещё не до конца понятна, не переживай. Разберём на следующем уроке» | Имя, сложная тема из заметки |
| Подбадривание к ДЗ | Есть активное ДЗ | «{Имя}, как продвигается задание? Если есть вопросы, не стесняйся написать, разберём до урока» | Имя, наличие ДЗ |
| Мотивация | streak >= 3 недель | «{Имя}, ты занимаешься уже {N} недель подряд. Это серьёзный результат» | Имя, streak |

### Хранение шаблонов

Файл `data/touch_templates.json`:

```json
{
  "progress": {
    "warm": [
      "{name}, на прошлом уроке разобрали {topic}. К следующему занятию попробуй заметить это в любом тексте на английском",
      "{name}, после того как мы прошли {topic}, хорошая идея: послушать подкаст или посмотреть видео на эту тему"
    ],
    "premium": [
      "{name}, мы с вами разобрали {topic}. Рекомендую обратить внимание на это в живом контексте до следующего занятия"
    ]
  },
  "support": { ... },
  "hw_nudge": { ... },
  "motivation": { ... }
}
```

Структура: `тип -> brand_tone -> список вариантов`. Бот выбирает случайный из списка с учётом `speech_style` (ты/Вы).

### Для пар

Касание приходит обоим участникам. Текст адаптирован: «вы с {партнёр} на прошлом уроке...» Шаблоны пар - отдельный ключ `_pair` в `touch_templates.json`.

### Управление

- Флаг `touches_enabled` в таблице `users` (DEFAULT true). Админ может отключить для конкретного ученика.
- Команда в карточке ученика: «Касания: вкл/выкл».

### Таблица `student_touches`

```sql
CREATE TABLE IF NOT EXISTS student_touches (
    id SERIAL PRIMARY KEY,
    student_id BIGINT NOT NULL REFERENCES users(telegram_id),
    template_type TEXT NOT NULL,
    template_key TEXT,
    context_source TEXT NOT NULL,     -- 'teacher_comment', 'homework', 'goal'
    context_snippet TEXT,             -- фрагмент, который был использован
    sent_at TIMESTAMP NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS student_touches_student_sent_idx
ON student_touches (student_id, sent_at DESC);
```

## 6. Компонент 4: Утренняя сводка (Morning Briefing)

### Проблема

Экран «Пульс» нужно открывать вручную. Хочется, чтобы бот сам утром говорил, что сегодня важно.

### Механика

Scheduler-джоб `morning_briefing` - каждый день в **09:00 МСК** отправляет админу одно сообщение.

### Вид сообщения

```
Доброе утро! Сводка на 5 мая, понедельник

Уроки сегодня: 3
   14:00 - Аня К.
   16:00 - Игорь + Маша
   18:30 - Дима Л.

Требует внимания:
   [!] Аня К. - ДЗ не отправлено (вчерашний урок)
   [!] Олег Р. - баланс 0, урок послезавтра
   [i] Катя С. - баланс 1 урок

Остальные 8 учеников - всё в порядке.
```

### Правила

- Если уроков нет И проблем нет - сводка не приходит (не спамить в выходные).
- Если есть проблемы, но нет уроков - приходит укороченная версия (только блок «Требует внимания»).
- Кнопки под сообщением: [Пульс] и [Отправить ДЗ] (быстрый переход к самому срочному ученику из красных).
- Данные берутся через общий `pulse_engine` - никакой дублирующей логики.
- Отключается через `/pulse off` (на случай отпуска). Включается `/pulse on`. Флаг хранится в `data/ops_status.json` (ключ `pulse_enabled`, default true).

### Callback-схема

- `briefing:pulse` - переход в Пульс
- `briefing:hw:{student_id}` - переход к отправке ДЗ самому срочному

## 8. Обработка ошибок

- Если `teacher_comment` пуст и нет активного ДЗ - касание не отправляется (тишина лучше мусора).
- Если ученик деактивирован (`is_active = false`) - исключается из всех компонентов.
- Если Telegram API недоступен при отправке касания/nudge - retry через 15 минут (максимум 3 попытки), затем пропуск.
- Все отправки логируются через `write_runtime_event()` для observability.

## 9. Тестирование

- Unit-тесты для `pulse_engine.py`: проверка логики светофора на граничных значениях (0/1/7/14 дней, баланс 0/1/2).
- Unit-тесты для `touch_engine.py`: парсинг заметок разных форматов, выбор шаблона, fallback-логика.
- Unit-тесты для nudge-эскалации: проверка переходов между ступенями, автозакрытие при отправке ДЗ.
- Integration-тесты: проверка scheduler-джобов на тестовых данных.
- Ручной smoke: `/pulse` показывает корректный светофор для текущей базы.
