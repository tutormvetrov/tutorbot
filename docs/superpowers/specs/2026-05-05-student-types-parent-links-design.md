# Разделение учеников (школьники / взрослые) + ручное управление привязкой родитель↔ученик

Дата: 2026-05-05

## Цель

Разделить учеников на два типа — **взрослые** и **школьники** — с разным стилем обращения, набором кнопок и логикой уведомлений. Дать админу ручной контроль над привязкой ученик↔родитель из карточки родителя.

---

## 1. Схема данных

### Новая колонка `student_type`

- Таблица: `users`
- Тип: `VARCHAR DEFAULT 'adult'`
- Значения: `adult`, `schoolchild`
- Миграция: `ALTER TABLE users ADD COLUMN IF NOT EXISTS student_type VARCHAR DEFAULT 'adult'`
- Все существующие ученики остаются `adult`

### Расширение `speech_style`

- Колонка уже существует: `speech_style VARCHAR` с значениями `formal` / `informal`
- Добавляется третье значение: `schoolchild`
- Изменений в схеме нет — поле уже VARCHAR

### Таблица `student_parent`

Без изменений. Новые методы для ручного управления используют существующую структуру.

---

## 2. Регистрация

### Новый шаг: выбор типа ученика

Добавляется **после ввода возраста**, **перед выбором языка**. Показывается только для ролей `student` и `student_pair`.

Текст:
> Вы взрослый ученик или школьник?

Кнопки:
- 🎓 Взрослый
- 🎒 Школьник

### Логика

| Выбор | `student_type` | `speech_style` |
|-------|---------------|----------------|
| Взрослый | `adult` | `formal` |
| Школьник | `schoolchild` | `schoolchild` |

### Счётчик шагов

- Роль `student`: `reg_total` увеличивается с 5 до 6
- Роль `student_pair`: `reg_total` увеличивается с 6 до 7

### Новое FSM-состояние

`Registration.waiting_for_student_type` — между `waiting_for_age` и `waiting_for_language`.

## 3. Клавиатура школьника

Отдельная клавиатура `schoolchild_main_keyboard` — копия `student_main_keyboard` без кнопки «💰 Оплата»:

```
📅 Расписание    📚 Домашка
📌 Учебный план
✉️ Написать преподавателю
📁 Материалы     📞 Контакты
📜 Правила       👤 Ещё
```

### Выбор клавиатуры

В `screens.py` при формировании домашнего экрана:
- `student_type == 'schoolchild'` → `schoolchild_main_keyboard`
- иначе → `student_main_keyboard`

### Заглушка для оплаты

Если школьник каким-то образом попадает в обработчик `payment` — показать:
> Информация об оплате доступна в кабинете родителя.

---

## 4. Стиль обращения

### Характеристики `speech_style = 'schoolchild'`

- Обращение на «ты»
- Неформальный, дружелюбный тон
- Молодёжные эмодзи и формулировки

### Примеры

| Контекст | `formal` | `schoolchild` |
|----------|----------|---------------|
| Напоминание о ДЗ | Напоминаем о домашнем задании | Не забудь про домашку 💪 |
| Напоминание об уроке | Напоминаем: через 10 минут урок | Через 10 минут урок, готовься! 🚀 |
| После урока | Спасибо за урок! | Урок прошёл, красавчик! 🔥 |

### Затронутые функции в `ui_text.py`

Все функции, где уже есть проверка `speech_style`, получают ветку `elif speech_style == 'schoolchild'`:

- Напоминания об уроке
- Напоминания о ДЗ
- Текст после урока (followup)
- Приветственные тексты
- Уведомления о прогуле
- Уведомления об оплате (для родителя, но на всякий случай)
- Текст реквизитов

## 5. Бизнес-логика для школьника

### Уведомления

Если `student_type == 'schoolchild'` и есть привязанный родитель:
- Уведомления об оплате → **только родителю**
- Уведомления о прогуле → **только родителю**
- Уведомления о балансе → **только родителю**

Если родителя нет → уведомления идут школьнику (fallback, чтобы информация не терялась).

### Блок «Оплата»

Школьник не видит кнопку «Оплата» в меню. При прямом попадании в обработчик — заглушка (см. п. 3).

## 6. Админ: управление привязкой родитель↔ученик

Управление происходит из **карточки родителя**.

### Привязка нового ученика

**Кнопка**: «➕ Привязать ученика» — в конце списка детей в карточке родителя.

**Поток**:
1. Нажатие кнопки → обработчик `admin:parent:link_student:{parent_id}`
2. Запрос: все активные ученики без активной записи в `student_parent`
3. Отображение списка (аналогично существующему паттерну `admin:student_pick_*`)
4. Выбор ученика → обработчик `admin:parent:pick_student:{parent_id}:{student_id}`
5. Создание записи в `student_parent`: `parent_id`, `student_id`, `student_info` из `full_name`, `is_active = true`
6. Возврат к карточке родителя — ребёнок в списке со статусом «привязан»

### Отвязка ученика

**Кнопка**: «✕ Отвязать» — рядом с каждым ребёнком в списке.

**Поток**:
1. Нажатие → обработчик `admin:parent:unlink:{link_id}:{parent_id}`
2. Подтверждение: «Отвязать {имя ученика} от {имя родителя}?»
3. Подтверждение → обработчик `admin:parent:unlink_confirm:{link_id}:{parent_id}`
4. `UPDATE student_parent SET is_active = false WHERE id = {link_id}`
5. Возврат к карточке родителя

### Данные обработчиков

| Действие | Данные обратного вызова |
|----------|------------------------|
| Начать привязку | `admin:parent:link_student:{parent_id}` |
| Выбрать ученика | `admin:parent:pick_student:{parent_id}:{student_id}` |
| Начать отвязку | `admin:parent:unlink:{link_id}:{parent_id}` |
| Подтвердить отвязку | `admin:parent:unlink_confirm:{link_id}:{parent_id}` |

## 7. Админ: переключение типа ученика

### Расположение

Карточка ученика → секция «⚙️ Настройки».

### Кнопка

Отображает текущий тип:
- «🎒 Тип: Школьник» (если сейчас `schoolchild`)
- «🎓 Тип: Взрослый» (если сейчас `adult`)

По нажатию — переключает на противоположный.

### Логика переключения

| Из | В (`student_type`) | В (`speech_style`) |
|----|-------------------|-------------------|
| `adult` | `schoolchild` | `schoolchild` |
| `schoolchild` | `adult` | `formal` |

### Данные обратного вызова

`admin:student_type_toggle:{telegram_id}:{page}`

## 8. Новые методы в слое БД

### `get_students_without_parent()`

Возвращает список активных учеников, у которых нет активной записи в `student_parent`. Используется для выбора ученика при ручной привязке.

### `create_parent_student_link(parent_id, student_id)`

Создаёт запись в `student_parent` с `is_active = true` и `student_info` из `full_name` ученика. Возвращает `id` созданной записи.

### `deactivate_parent_student_link(link_id)`

`UPDATE student_parent SET is_active = false WHERE id = {link_id}`. Возвращает `True` при успехе.

### `toggle_student_type(telegram_id)`

Переключает `student_type` и `speech_style` синхронно (см. таблицу в п. 7). Возвращает новый `student_type`.

---

## 9. Миграция

Одна миграция в `schema.py` → `migrate_users_add_student_type()`:

```sql
ALTER TABLE users ADD COLUMN IF NOT EXISTS student_type VARCHAR DEFAULT 'adult'
```

Регистрируется в `create_all_tables()` после существующих миграций.

Авто-миграция данных не требуется — все ученики остаются `adult`. Админ переключает вручную.

---

## 10. Что не входит

- Автоматическое определение типа по возрасту
- Изменение родительского меню
- Другие типы учеников (корпоративный, дошкольник и т.д.)
- Изменение схемы таблицы `student_parent`
- Отдельный онбординг для школьников (кроме стиля текстов)
