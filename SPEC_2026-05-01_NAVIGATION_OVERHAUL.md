Дата: 01.05.2026
Автор: brainstorm + спецификация
Статус: черновик, готов к реализации поэтапно
Связанный коммит-предшественник: `52b47e7` (вынесли «📅 Расписание», «📁 Материалы», убрали дубли «💳 Реквизиты», календарь перенесли с Контактов в экран Расписания, добавили авто-приглашение к оплате после первого урока)

## 1. Цель и не-цели

### Цель
Унифицировать навигацию во всех ролях бота (ученик, ученик-в-паре, родитель, админ-преподаватель), чтобы:
- любая частая операция была доступна за ≤3 нажатия;
- главные экраны не превышали 6 кнопок;
- редкие операции были обнаружимы, но не «съедали» главную;
- админ видел оперативную картину «что нужно сделать сегодня» без копания в подменю;
- ответы учеников и заявки не терялись в общем чате.

### Не-цели
- Не меняем сценарии регистрации, FSM, бизнес-логику доменных операций (заморозка/оплата/ДЗ).
- Не вводим вкладочную метафору (отдельная гипотеза C из brainstorming) — отвергнута из-за лимита `edit_message_text`.
- Не заменяем существующие маршруты команд (`/start`, `/menu`, `/profile`, `/help`); все они остаются.

### Принципы дизайна (применяются ко всем этапам)
1. **Frequency-first** — частое выше и левее.
2. **Один путь = одна кнопка** — никаких дублирующих маршрутов.
3. **Глаголы вместо существительных** — особенно для админа.
4. **Не больше 6–7 кнопок на экране**.
5. **Редкое прячем за «👤 Ещё»**, но никогда не глубже двух кликов от главной.
6. **Контекстные шорткаты** — после оплаты/первого урока/завершения ДЗ предлагать следующее логичное действие.

## 2. Этап 1 — компактные главные клавиатуры (низкий риск)

## 4. Этап 3 — Inbox, светофоры родителя, stateful home

### 4.1 «💬 Inbox» — единая лента входящих для админа

**Сейчас:**
- Ответы учеников через `reply:*` уходят админу как обычные сообщения в чат (`bot.send_message(ADMIN_ID, ...)`).
- При большом потоке (4+ за день) теряются между ботскими нотификациями.
- Нет возможности посмотреть «непрочитанные» или «новые за сутки».

**Новое:**
- Таблица `admin_inbox` (или generalized: `admin_events`):
  ```sql
  CREATE TABLE admin_inbox (
      id SERIAL PRIMARY KEY,
      kind TEXT NOT NULL,                     -- 'reply', 'freeze_request', 'first_contact'
      payload JSONB NOT NULL,                 -- {student_id, context, message_text, ...}
      created_at TIMESTAMP DEFAULT now(),
      read_at TIMESTAMP,
      handled_at TIMESTAMP,
      handled_by BIGINT
  );
  CREATE INDEX admin_inbox_unread_idx
      ON admin_inbox (created_at DESC)
      WHERE handled_at IS NULL;
  ```
- При получении ответа ученика (`reply:*` в `start_student_reply` / `process_student_reply`):
  - текущая логика «отправить админу в чат» сохраняется (тёплая нотификация);
  - **дополнительно** пишем строку в `admin_inbox`.
- При создании заявки на заморозку — туда же.
- При новой регистрации (родитель в статусе ⏳) — туда же.

**Экран «💬 Inbox» (callback `admin:inbox`):**
```
💬 Inbox · 4 непрочитанных

🆕 Сегодня
   • 14:32 · Иван (по ДЗ): «Не понял задание №3»
   • 12:15 · Мария (по оплате): «Перевела по СБП»

📬 Вчера
   • 18:00 · Костя (общий): «Можно урок передвинуть?»
   • 09:42 · родитель Анны: «Когда ближайший?»

[📨 Открыть #1] [✓ Отметить всё прочитанным]
[◀️ К панели]
```

Каждый элемент по тапу — открывает подробную карточку с двумя действиями: «Ответить» (FSM `StudentReply` или новый `AdminInboxReply`) и «✓ Закрыть».

Преимущества:
- Не теряются ответы.
- Можно метрировать: сколько в среднем висит непрочитанным, средний lag ответа.

### 4.2 Светофоры в карточке родителя

В `make_parent_home_keyboard` сейчас иконка просто `✅` или `⏳`. Расширим до светофора:
- 🟢 — у ребёнка есть ближайший урок и ДЗ под контролем
- 🟡 — есть просроченное ДЗ или баланс ≤1 урока
- 🔴 — нет ближайшего урока ИЛИ баланс 0 ИЛИ ученик не отвечал >7 дней
- ⏳ — ребёнок ещё не подтвердил связь с родителем

Источник данных — расширенный `get_parent_children_overview` (сейчас он возвращает базовые поля; добавляем `last_lesson_date`, `next_lesson_date`, `overdue_homework_count`, `lesson_balance`, `last_message_at`).

Текст шапки `build_parent_home_text` тоже подтягивает топ-1 проблему ребёнка для каждого:
```
👨‍👩‍👧 Кабинет родителя

👶 Дети:
🟢 Анна — урок завтра в 17:00, всё в норме
🟡 Костя — ДЗ просрочено на 1 день
⏳ Маша — ждём подтверждения связи

[🟢 Анна] [🟡 Костя] [⏳ Маша]
[💰 Все оплаты]
[✉️ Написать преподавателю]
[📁 Материалы] [📞 Контакты]
[👤 Ещё]
```

### 4.3 Stateful student home — динамический CTA

В `build_student_home_text` сейчас есть лёгкая адаптация («Сначала стоит проверить расписание...»). Расширить:
- Если до урока ≤15 минут → шапка «Урок начинается через 12 мин · [📞 VK Звонок]» (URL-кнопка наверху клавиатуры).
- Если есть просроченное ДЗ → «⚠️ ДЗ просрочено: …»
- Если баланс 0 → «💸 На балансе нет уроков. Оплатите ближайшую неделю.»
- Если только что зарегистрировался и не прошёл тест уровня → «🧪 Пройдите тест уровня — это 10 минут».

CTA — одна, по приоритету (в указанном порядке). Реализация — функция `compute_student_cta(user, balance, next_lesson, homework, ...)` возвращает `{kind, text, button_label, button_callback_or_url}` или `None`.

При наличии CTA в клавиатуру **первой строкой** добавляется одна кнопка от CTA (URL для VK-звонка, callback для остального). Это не ломает существующий layout — просто добавляет приоритетную строку наверх, когда есть что показать.

## 5. Этап 4 — опциональные эффективные мелочи

Делается после 1–3, по желанию. Не входит в обязательный объём.

### 5.1 Slash-команды как ярлыки

- `/today` → тот же экран, что «🎯 Сегодня» (для админа) или «main menu» (для не-админа).
- `/freeze` → сразу `freeze_keyboard`.
- `/plan` → `study_plan_keyboard`.
- `/materials` → экран материалов.
- `/health` → `admin:health` для админа.

Регистрируем в `BotCommands` (в `app.py` `set_my_commands`), чтобы Telegram показывал их в выпадающем списке `/`. Не для всех ролей одинаковый список — у админа добавляются `/today`, `/health`.

### 5.2 Pinned dashboard message

Один раз создать pinned-сообщение в чате с ботом (для каждого ученика и родителя), которое **обновляется по событиям** (не нажатию):
- следующий урок
- баланс
- активные ДЗ
- кнопка «✉️ Написать»

Apscheduler-job + событийные хуки (после оплаты, после нового ДЗ) обновляют pinned. Большая работа — отдельный спринт.

### 5.3 Inline-mode (`@bot ...`)

Опционально: ученик в любом чате может набрать `@my_tutormvetrov_bot заплатить` — бот выдаст inline-карточку с реквизитами. Малая ценность, не приоритет.

## 6. Кросс-cutting

### 6.1 Миграции БД

| Этап | Миграция |
|---|---|
| 1 | нет |
| 2 | нет (агрегатор «Сегодня» — только запросы, без новых таблиц) |
| 3 | `admin_inbox` (CREATE TABLE), расширение `get_parent_children_overview` (вьюха или подзапрос) |
| 4 | `pinned_dashboard_messages (user_id, message_id, last_synced_at)` |

Все миграции идемпотентные, через `migrate_*` стиль файлов в `utils/db_api/schema.py` + бэкап перед релизом (`scripts/db_backup.py`).

### 6.2 Совместимость и rollout

- Все этапы делаются **отдельными PR'ами и отдельными релизами** — это снижает риск.
- Этап 1 безопасен: нет миграций, нет новой бизнес-логики, только перестановка кнопок.
- Этап 2 требует одного backfill-запроса при первой загрузке экрана «Сегодня» — кешируем результат в памяти на 60с, чтобы не молотить базу.
- Этап 3 добавляет таблицу `admin_inbox`. Существующие нотификации продолжают работать. Inbox дополняет, не заменяет.

### 6.3 Коммуникация пользователям

Один разовый ручной broadcast после релиза этапа 1:

Делается через `admin:broadcast → ✏️ Своё сообщение → ☑️ Все`, не автоматически.

### 6.4 Quality gate (для каждого этапа)

- `make check` (ruff + mypy + pytest + compileall) — must pass.
- `make smoke` — ok локально и на runtime.
- `scripts/db_backup.py` — резервная копия перед релизом, особенно для этапа 3.
- После `systemctl restart tutorbot`: проверка, что планировщик запустил все ожидаемые job'ы (логи), и `scripts/healthcheck.py --mode runtime` отдаёт `ok`.
